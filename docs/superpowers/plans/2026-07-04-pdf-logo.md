# PDF Header Logo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the static `"LOGO"` placeholder in the generated PDF header with a real logo image once one is dropped into `public/logo.png`, with no code changes needed at that point.

**Architecture:** A new `lib/pdf-template/logo.ts` reads `public/logo.png` from disk and returns a base64 data URI (or `null` if the file is absent). `renderHenkatenHtml.ts` uses that data URI to render an `<img>` in place of the `"LOGO"` text; `pdf-styles.ts` gets a matching `.logo-img` rule so the image fits the existing box.

**Tech Stack:** Node.js `fs`/`path` (server-side, `runtime = "nodejs"` already set on the API route), Vitest.

## Global Constraints

- Fixed path only: `public/logo.png` — no other filenames/formats supported (spec Non-goals: YAGNI).
- No relative `<img src="/logo.png">` — PDF rendering has no HTTP server context (spec Non-goals; `generatePdfBuffer.ts:20` uses `page.setContent()`).
- Must never throw or break PDF generation when the logo file doesn't exist — falls back to the current `"LOGO"` text (spec Goals).
- Scoped to PDF output only — no Navbar/web UI changes (spec Non-goals).

    const pngBytes = Buffer.from([0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a]);

- [ ] **Step 3: Implement `getLogoDataUri`**

Create `lib/pdf-template/logo.ts`:

```typescript
import { readFileSync } from "fs";
import path from "path";

export function getLogoDataUri(
  logoPath: string = path.join(process.cwd(), "public", "logo.png")
): string | null {
  try {
    const bytes = readFileSync(logoPath);
    return `data:image/png;base64,${bytes.toString("base64")}`;
  } catch {
    return null;
  }
}
```
